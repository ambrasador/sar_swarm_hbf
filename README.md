## Головні результати (підтверджувальні карти 11–60; усі числа — з `analysis_s1.json`)

Заморожено до прогону: HBF = 3 гіпотези ρ ∈ {0,05; 0,3; 0,8}, апріорні ваги (0,5; 0,25; 0,25), β = 1;
конкурент HEDAC*-ε* з ε* = 0,2 (обрано на картах розроблення 100–159).

| Метод | J̄ (середнє за 7 умовами) | R (найбільше відставання від найкращого ε) |
|---|---|---|
| HBF | 0,712 | 0,016 |
| HBF-fix (β = 0) | 0,709 | 0,026 |
| HEDAC*-ε*, ε* = 0,2 | 0,703 | 0,044 |
| HEDAC*-ε, ε = 0,4 (найкраще заднім числом) | 0,712 | 0,029 |
| HEDAC* (ε = 0,05) | 0,690 | 0,103 |
| BSS | 0,690 | 0,059 |

| Гіпотеза | D (95 % ДІ) | p (Холм) | Рішення |
|---|---|---|---|
| H1: HBF > HEDAC*-ε* | +0,010 [−0,003; 0,022] | 0,269 | не підтверджено |
| H2: HBF > HEDAC* | +0,022 [0,012; 0,033] | 0,003 | підтверджено |
| H3: HBF > BSS | +0,022 [0,011; 0,032] | 0,002 | підтверджено |
| H5: HBF > HBF-fix | +0,004 [−0,004; 0,012] | 0,350 | не підтверджено |
| H4: ціна за правильної карти ≤ 0,02 | S1: −0,015 [−0,026; −0,004] | 0,18 (не-гіршість) | не підтверджено |
| H6: стійкість до налаштування | розкид HBF 0,009 проти ε 0,022 | — | підтверджено (описово) |

Коротко: HBF не потребує вгадувати рівномірну домішку ε. Найкраще статичне ε на картах розроблення було 0,2,
на підтверджувальних — 0,4; HBF з налаштуванням, обраним на картах розроблення, досягає середньої якості найкращого ε
і має найменше відставання в найгіршій умові. Він значуще кращий за HEDAC* з типовим ε і за BSS. Значущої переваги
в середньому над ε*, підібраним на картах розроблення, немає; внесок онлайн-навчання ваг незначущий
(Твердження 2–3 статті пояснюють чому).

## Розширення (версія 2.2): S4, N_v, реальна місцевість, S4-M

Протокол `code/PROTOCOL_S4.md` зафіксовано до підтверджувального прогону на картах 61–99; розроблення HBF-S виконано
лише на картах 100–139 (`code/dev_s4/`, правило другого етапу `STAGE2_RULE_S4.md`).
Числа — з `analysis_s4_main.json`, `analysis_s4_nv.json`, `analysis_s4_real.json`, `analysis_s4_mis.json`.

| Результат | Значення |
|---|---|
| HBF-S проти найкращого статичного ε* (H7, первинна; карти 61–99) | +0,015, ДІ [0,008; 0,022], p(Холм) < 0,001; до +0,097 в умові A80 |
| HBF-S проти HBF-U / HEDAC* (H8, H10) | +0,026 / +0,016, підтверджено |
| Внесок навчання ваг, HBF-S проти HBF-S-fix (H9) | +0,005, **не підтверджено** (значущий лише за сильної помилки) |
| Ціна за правильної карти (H11, межа 0,02) | −0,019 (A0), −0,016 (B0), **не-гіршість не підтверджено** |
| Вплив N_v на виграш навчання (H12) | +0,008, **не підтверджено** |
| Реальна місцевість (OSM, Карпати), HBF проти HEDAC*-0,2 (H13–H16) | −0,005, **жодної гіпотези не підтверджено** |
| S4-M, істина поза класом гіпотез (протокол `PROTOCOL_S4M.md`, карти 160–199) | HBF-S проти HEDAC*-ε* (H17): −0,006, ДІ [−0,022; 0,011], **не підтверджено**; проти HBF-U (H19): −0,037, p(Холм) = 0,005 — HBF-S **гірший** |

У S4-M вид M (хибна відстань зсуву) виграш зберігає (+0,061 в M80), вид N (істина — інша ділянка) дає програш
(−0,056 в N80).

## Відтворення (Windows або Linux, Python ≥ 3.10, NumPy, SciPy; див. `code/requirements.txt`)

```
cd code
sha256sum -c PROTOCOL_S1.sha256 PROTOCOL_S4.sha256 PROTOCOL_S4M.sha256   # протоколи не змінювалися
python tests_s1.py                         # HBF з K = 1 побітово відтворює HEDAC* і HEDAC*-ε; β = 0 — сталі ваги
python tests_s4.py                         # HBF-S з рівномірними гіпотезами відтворює HEDAC* / HBF
python verify_s1.py                        # контроль відтворюваності HEDAC* проти архіву (60 з 60)

# статистичний аналіз із журналів прогонів
python analysis_s1.py results results results frozen.json ../analysis_s1.json
python analysis_s4.py configs_s4/analysis_main.json ../analysis_s4_main.json   # так само analysis_nv, analysis_real, analysis_mis

# прогони заново (години; перервані продовжуються з журналу)
python run_suite_s1.py --workers 4
python trace_s1.py --workers 4
python run_s4.py --config configs_s4/conf_main.json --workers 4
python run_s4.py --config configs_s4/conf_nv.json --workers 4
python run_s4m.py --config configs_s4/conf_mis.json --workers 4
python run_s4_real.py --config configs_s4/real_main.json --workers 4      # і real_eps.json

cd ../figures && python make_figs.py ../analysis_s1.json ../code/results/s1_trace/trace.json . && python make_fig4.py
```

Розроблення (необов'язково; результати вже в `code/dev/*.json` і `code/dev_s4/`):
`cd code/dev && python dev_r1.py && python dev_r2.py && python dev_r3.py && python dev_r3b.py && python dev_r4a.py && python dev_r4b.py`,
потім `cd .. && python make_protocol.py` (відтворює вибір і протокол; дата фіксації в протоколі зміниться).

Прогони детерміновані: зерна залежать лише від сценарію, карти й розстановки, тому повторний запуск дає ті самі
значення SWS (на іншій ОС можливі розбіжності в останніх знаках через бібліотеки лінійної алгебри).

Перевірено 18.11.2026 (Python 3.13, NumPy 2.5, SciPy 1.18, Linux): контрольні суми трьох протоколів збігаються;
`tests_s1.py`, `tests_s4.py` пройдено; `verify_s1.py` — 60 з 60; усі значення `analysis_s1.json` і чотирьох
`analysis_s4_*.json` (3197 чисел) відтворюються з журналів без розбіжностей; 24 вибрані екземпляри S4, N_v, S4-M
і реальної місцевості, прогнані заново, дали ті самі моменти виявлення й SWS, що в журналах.

## Код

Файли моделей пакета sar_swarm v2 (`env.py`, `baselines.py`, `novel.py`, `hybrid.py`, `ext_env.py`,
`run_experiments.py`, …) скопійовано з пакета без змін (SHA-256 збігаються). Нове:

* `hbf.py` — клас `HBF` (запропонований метод); `variants_s1.py` — реєстрація HBF, абляції HBF-fix (β = 0)
  і налаштувань для аналізу чутливості (створено `make_configs.py` із `frozen.json`);
* `run_s1.py` — обгортка раннера (додає `hbf.py`, `variants_s1.py` до хешу коду); `run_suite_s1.py` — усі прогони
  підтвердження S1; `trace_s1.py` — телеметрія ваг гіпотез; `analysis_s1.py` — статистичний аналіз за протоколом S1;
* `make_protocol.py` — механічний відбір остаточної конфігурації за результатами розроблення й запис протоколу;
  `make_configs.py` — конфігурації підтвердження;
* `tests_s1.py` — HBF з K = 1 побітово відтворює HEDAC* і HEDAC*-ε, остаточна конфігурація побітово збігається
  з класом, на якому вели розроблення (`dev/bmaf.py`), за β = 0 ваги сталі; `verify_s1.py` — HEDAC* проти архіву;
* `hbf_s.py` — HBF-S (гіпотези — пари «частка, альтернативна карта») і довідковий ORACLE-S; `s4_env.py`,
  `s4m_env.py` — сценарії S4 і S4-M; `run_s4.py`, `run_s4m.py`, `run_s4_real.py` — раннери; `make_dev_s4.py`,
  `dev_sum_s4.py`, `make_protocol_s4.py` — розроблення й протокол S4; `analysis_s4.py` — аналіз; `tests_s4.py`,
  `tests_s4m.py` — перевірки;
* `realmap.py` — растеризація карти OpenStreetMap у сітку моделювання.
