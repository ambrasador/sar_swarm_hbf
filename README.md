## Головні результати (підтверджувальні карти 11–60; усі числа — з `analysis_s1.json`)

Заморожено до прогону: HBF = 3 гіпотези ρ ∈ {0,05; 0,3; 0,8}, апріорні ваги (0,5; 0,25; 0,25), β = 1;
конкурент HEDAC*-ε* з ε* = 0,2 (обрано на картах розроблення 100–159).

| Метод | J̄ (середнє за 7 умовами) | R (найбільше відставання від найкращого ε) |
|---|---|---|
| HBF | 0,712 | 0,016 |
| HBF-fix (β = 0) | 0,709 | 0,026 |
| HEDAC*-ε*, ε* = 0,2 | 0,703 | 0,044 |
| HEDAC*-ε, ε = 0,4 (найкраще заднім числом) | 0,712 | 0,029 |
| HEDAC* (ε = 0,05) | 0,690 | 0,103 |
| BSS | 0,690 | 0,059 |

| Гіпотеза | D (95 % ДІ) | p (Холм) | Рішення |
|---|---|---|---|
| H1: HBF > HEDAC*-ε* | +0,010 [-0,003; 0,022] | 0,269 | не підтверджено |
| H2: HBF > HEDAC* | +0,022 [0,012; 0,033] | 0,003 | підтверджено |
| H3: HBF > BSS | +0,022 [0,011; 0,032] | 0,002 | підтверджено |
| H5: HBF > HBF-fix | +0,004 [-0,004; 0,012] | 0,350 | не підтверджено |
| H4: ціна за правильної карти ≤ 0,02 | S1: −0,015 [−0,026; −0,004] | 0,18 (не-гіршість) | не підтверджено |
| H6: стійкість до налаштування | розкид HBF 0,009 проти ε 0,022 | — | підтверджено (описово) |

Коротко: HBF значуще кращий за HEDAC* з типовим ε і за BSS, має найменше відставання в найгіршій умові й досягає
середньої якості найкращого статичного ε, яке заздалегідь невідоме (на картах розроблення найкращим було 0,2, на
підтверджувальних — 0,4). Значущої переваги над ε*, підібраним на картах розроблення, немає; внесок онлайн-навчання
ваг незначущий (Твердження 2–3 статті пояснюють чому).

## Код

Файли моделей пакета (`env.py`, `baselines.py`, `novel.py`, `hybrid.py`, `ext_env.py`, `run_experiments.py`, …)
скопійовано без змін з `D:\diser\code` (SHA-256 збігаються). Нове:

* `hbf.py` — клас `HBF` (запропонований метод);
* `variants_s1.py` — реєстрація HBF, абляції HBF-fix (β = 0) і налаштувань для аналізу чутливості
  (створено `make_configs.py` із `frozen.json`);
* `run_s1.py` — обгортка раннера (додає `hbf.py`, `variants_s1.py` до хешу коду); `run_suite_s1.py` — усі прогони;
* `tests_s1.py` — перевірки: HBF з K = 1 побітово відтворює HEDAC* і HEDAC*-ε; остаточна конфігурація побітово
  збігається з класом, на якому вели розробку (`dev/bmaf.py`); за β = 0 ваги сталі;
* `trace_s1.py` — телеметрія ваг гіпотез; `analysis_s1.py` — статистичний аналіз за протоколом;
* `make_protocol.py` — механічний відбір остаточної конфігурації за результатами розроблення і запис протоколу;
* `make_configs.py` — конфігурації підтвердження.

## Відтворення (Windows або Linux, Python ≥ 3.10, NumPy, SciPy)

```
cd code
python tests_s1.py                         # перевірки коректності
python run_suite_s1.py --workers 4         # усі підтверджувальні прогони (продовжує перервані)
python verify_s1.py                        # контроль відтворюваності HEDAC* проти архіву
python trace_s1.py --workers 4             # телеметрія ваг гіпотез
python analysis_s1.py results results results frozen.json ../analysis_s1.json
cd ../figures && python make_figs.py ../analysis_s1.json ../code/results/s1_trace/trace.json .
```

Розроблення (необов'язково; результати вже в `code/dev/*.json`):
`cd code/dev && python dev_r1.py && python dev_r2.py && python dev_r3.py && python dev_r3b.py && python dev_r4a.py && python dev_r4b.py`,
потім `cd .. && python make_protocol.py` (відтворює вибір і протокол; дата фіксації в протоколі зміниться).

Прогони детерміновані: зерна залежать лише від сценарію, карти й розстановки, тому повторний запуск дає ті самі
значення SWS (на іншій ОС можливі розбіжності в останніх знаках через бібліотеки лінійної алгебри).
